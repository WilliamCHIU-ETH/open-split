# ADR-0005：LIFF 是同一套帳本；LINE 沒有聊天機器人

- 狀態：已接受；「Google 登入仍然只是次要入口」由 [ADR-0009](0009-mcp-identity-via-line.md) 改為延後到上線後再決定。
- 日期：2026-11-20

## 背景

朋友已經在 LINE 群裡說話。擁有者希望帳本能在那個 App 裡打開，也能把一張帳單卡片丟回群裡。他不希望群組裡多一個會回話的機器人，也不希望記事只能在電腦瀏覽器完成。

## 決策

LINE Login 是主要登入。LIFF 是**同一套帳本網頁**在 LINE 裡打開，並帶著這個人的 LINE 身份。Google 登入仍然只是次要入口，給不在 LINE 裡的時候用。

### LIFF 可以做

- 打開與一般瀏覽器相同的帳本網頁。
- 使用打開 LIFF 的那個人的 LINE 身份，當作已登入的使用者。
- 做帳本網頁能做的每一件事，包含記帳、改帳、作廢、看餘額、結清、管理成員與邀請。在 LIFF 裡記帳是正常路徑，不是例外。
- 用 `liff.shareTargetPicker()` 把 Flex Message 卡片分享到聊天。卡片是分享，不是機器人發言。

### LIFF 與 LINE 不能做

- 不做對話式聊天機器人。沒有「跟帳本說話」的 LINE 聊天室。
- 不讀取群組聊天內容來決定怎麼分帳。自然語言發生在擁有者自己的外部代理人，代理人再經 MCP 寫入。
- 不把官方帳號做成會回訊息的客服。可選的官方帳號只是安靜的推播通道：綁定群組的 `groupId`（或使用者 id），用 Messaging API push 送帳單或提醒卡片。沒有 webhook 回覆流程。
- 不在 LIFF 裡提供另一套縮水的「只能看通知」介面。若某個操作在瀏覽器帳本裡有，在 LIFF 裡也要有。
- 不把假的開發用身份放進 LIFF 的前端。見 [ADR-0003](0003-auth-separation.md)。

朋友繼續在群裡正常聊天。擁有者對自己的代理人說話，發生在 LINE 外面。

## 後果

- 網頁必須在 LINE 內建瀏覽器（iOS WKWebView、Android WebView）裡可用，不只在桌面 Chrome。見 [前端品質](../frontend-quality.md)。
- 分享卡片與推播是後續切片。這次只在 driver 裡建立邀請連結，並在文件裡把邊界寫死。
- 「LINE 只做通知與分享」這句話，範圍只到機器人不存在、官方帳號不回話。它不限制 LIFF 裡的帳本功能。

## 不採用

用 LINE Messaging API 的 webhook 做一個群組機器人來記帳。那會把人與人的聊天，變成對機器人下指令，也會和「外部代理人經 MCP 記帳」重複。
