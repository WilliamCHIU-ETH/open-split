# ADR-0002：網頁與 MCP 共用一個確定性的帳本核心

- 狀態：已接受
- 日期：2026-11-20

## 背景

網頁與外部代理人都會寫入同一本帳。如果各算各的，餘額會分叉，性質測試也只覆蓋其中一套。

## 決策

分帳、餘額與債務簡化只存在於 `packages/core`。它是純函式：沒有 I/O、沒有 Workers、沒有資料庫、沒有網路，也沒有執行期依賴。

金額是整數最小貨幣單位，型別是帶品牌的 `bigint`（`Minor`）。JSON 與 CLI 用十進位整數字串，避免 JavaScript 的 `number`。唯一的 `number` 邊界是 `minorFromSafeInteger`，呼叫後不得再把金額留在 `number`。

份額的餘數分配是契約的一部分：先依參與者 id 的字典序，均等分時餘數給較早的 id；份數與百分比用最大餘數法，同分再以 id 排序。這會穩定地把零頭分給較早的 id。要改這個順序，必須當成刻意的契約變更。

百分比用基點（100% = 10000），不用浮點百分比。匯率在切片 4 會是兩個整數相除，仍然留在 core。

Web API 與 MCP 的 Zod schema 只定義在 `packages/contracts`。

## 後果

- `apps/worker` 與 `apps/web` 不得自己實作 `computeBalances`、`allocate`、`simplifyDebts`。ESLint 會拒絕，訊息裡寫了原因。
- core 裡的浮點字面值、以及 core 對 `node:`／資料庫／框架的匯入，會讓檢查失敗。
- 性質測試鎖四件事：餘額合計為 0、份額合計等於原金額、簡化後每人為 0、轉帳數 ≤ 參與者 − 1。

## 不採用

在 Worker 裡用 SQL 直接把金額除開。那會讓 MCP 與網頁各寫一次，也讓浮點或整數除法的差異無法用同一組測試盯住。
