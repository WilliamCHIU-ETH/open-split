# ADR-0004：虛擬成員先記帳，之後再認領

- 狀態：已接受
- 日期：2026-11-20

## 背景

一起吃飯的人常常還沒註冊。若必須等每個人登入才能記帳，這本帳就不會被用。

## 決策

群組成員（`group_members`）可以沒有 `user_id`。沒有 `user_id` 的是虛擬成員：有顯示名稱，可以被分到份額，但不能自己登入操作。

認領時，本人經由邀請或認領權杖把 `user_id` 填上，並寫下 `claimed_at`。既有的支出份額仍然指向同一個 `group_members.id`，不把歷史搬到另一筆成員。餘額不用重算。

權杖只存雜湊。虛擬成員不能使用 MCP。

## 後果

- 帳本數學只認識參與者 id，不認識他有沒有登入。虛擬與否是 Worker 的授權問題，不是 core 的問題。
- 活動紀錄要能看出「建立虛擬成員」與「認領」是兩件不同的事。
- driver 的 `add-member --virtual` 只在本機狀態檔模擬這件事，方便切片 2 之前就有一條可跑的流程。

## 不採用

用假的 `users` 列代表還沒來的朋友。那會讓「沒有登入」與「真的有帳號」混在一起，認領時還得合併兩個使用者。
